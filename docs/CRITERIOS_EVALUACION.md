# Criterios de evaluación de la prueba

## Criterios porcentuales

La prueba indica los siguientes criterios:

| Criterio | Peso |
|---|---:|
| Funcionamiento | 40 % |
| Diseño POO | 25 % |
| Calidad del código | 15 % |
| Defensa y modificación | 20 % |

## Qué significa para este proyecto

### Funcionamiento — 40 %

Los ejercicios deben cumplir los requisitos, validar entradas y contemplar casos límite.

### Diseño POO — 25 %

Se presta atención a:

- responsabilidad de las clases;
- encapsulación;
- herencia;
- composición;
- polimorfismo.

### Calidad del código — 15 %

Se busca:

- nombres comprensibles;
- estructura clara;
- reducción de duplicación;
- código legible.

### Defensa y modificación — 20 %

El alumno debe ser capaz de:

- explicar las clases;
- justificar decisiones;
- detectar errores;
- predecir resultados;
- realizar una pequeña modificación en directo.

## Selección de ejercicios

La prueba indica que deben seleccionarse **exactamente 5 de los 10 ejercicios**.

Puntuaciones máximas indicadas:

| Ejercicio | Puntos |
|---:|---:|
| 1 | 0,5 |
| 2 | 0,6 |
| 3 | 0,8 |
| 4 | 0,8 |
| 5 | 1,0 |
| 6 | 0,8 |
| 7 | 1,2 |
| 8 | 2,1 |
| 9 | 2,7 |
| 10 | 3,3 |

Para aprobar se requiere un mínimo de **5 puntos sobre 10** y debe seleccionarse al menos uno de los ejercicios **8, 9 o 10**.

## Uso de recursos

La prueba permite apuntes, documentación, Internet y herramientas de IA, pero exige que el alumno pueda comprender, explicar y modificar lo que entrega.

## Cómo ayuda el laboratorio

El laboratorio está diseñado especialmente para la defensa:

```text
Cambiar un valor
→ predecir
→ ejecutar
→ observar el estado
→ explicar el motivo
```

La guía detallada de defensa se encuentra en `EXPLICACION_PROFESOR.md`.
